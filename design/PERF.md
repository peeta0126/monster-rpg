## 분석 (2026-08-08 · 개선 후)

측정 조건: `vite preview` 는 gzip 을 적용한다. 위 전송량은 **압축 후 실제 바이트**다.

### 이전 대비

| 화면 | 전송량 (전 → 후) | Slow 3G 로드 (전 → 후) |
| --- | --- | --- |
| 베이스캠프 | 2096 → **1436KB** | 44.3s → **30.7s** |
| 전투 | 1234 → **578KB** | 26.1s → **13.3s** |
| 숲 | 1673 → **303KB** | 34.7s → **3.4s** |

세 가지를 했다.

**1. 폰트 서브셋 — 1207KB → 65KB (95%)**
Galmuri 원본은 20,965 글리프고 그중 한자가 6,777자다. 게임에는 한자도 가나도 한 글자
안 나온다. 화면에 뜨는 한글은 전부 소스에 박혀 있어서(사용자가 한글을 입력할 수 있는
곳이 없다 — 아이디는 서버에서 ASCII 로 막고, 몬스터 nickname 은 설정 UI 가 없다)
소스를 훑어 실제 쓰인 1,061자만 남겼다. `scripts/subset-fonts.mjs`, **빌드에 물려 있다.**

**2. 라우트 코드 스플리팅 — 캔버스 없는 화면에서 phaser 325KB 제거**
`React.lazy` 로 라우트를 갈랐다. 다만 그것만으로는 안 됐다 — `shared/phaser/events.ts` 가
`Phaser.Events.EventEmitter` 하나 때문에 phaser 를 물고 있었고 `main.tsx` 가 그 파일을
임포트해서 엔트리에 딸려왔다. 버스를 40줄짜리 자체 구현으로 바꿔 끊었다.

**3. 흐린 배경 저해상도 사본 — 517KB → 140KB**
`GameBackground` / `ForestBackground` 는 `blur(10~14px) + brightness(0.3)` 으로 뭉개서
쓴다. 640px 사본이면 블러 후 구분이 안 된다. 베이스캠프 씬은 계속 원본을 쓴다.

### 남은 것

베이스캠프 1436KB 는 basecamp-bg 517 + basecamp-bg-1 390 + phaser 325 다. 앞의 둘은
Phaser 씬이 실제로 그리는 필드 배경(1536×2730)이라 줄이려면 화질을 포기해야 한다.
지금은 여기가 바닥으로 보인다.

FPS 는 두 화면 다 60/60 고정이다.

### 잘 되고 있는 것 (그대로)

- 씬별 지연 로딩. 전투는 몬스터 2장(78KB)만 받는다. 15장을 아틀라스로 묶었다면
  전투마다 전부 받았을 것 — 아틀라스를 만들지 않은 판단이 여기서 확인된다.
