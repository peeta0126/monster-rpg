## 심사 기준별 대응

| 기준 | 이 게임에서 보여 줄 것 |
|---|---|
| **플레이성** | 링크를 열면 「바로 시작」 하나로 게임이 시작된다. 가입도 설치도 없다. 전투는 자동 진행 토글이 있어 심사 중에도 빠르게 훑어볼 수 있다 |
| **독창성** | 성장이 레벨이 아니라 **제작**에 걸려 있다. 6레벨 아래 층의 경험치를 0으로 만드는 규칙(`expLevelGapMultiplier`)이 레벨 노가다를 막고, 5층마다 오는 관문은 장비를 갖춰야만 넘어간다. 숲 원정은 되돌아갈 수 없는 선형 구조에 「소란도」가 붙어, 더 들어갈지 지금 정산할지를 매 걸음 고르게 한다 |
| **Codex 협업** | 아래 「Codex 항목에 대해」 참고. 개발 과정 기록은 `docs/DEV_PROCESS.md` |
| **출시 가능성** | 계정·세이브 서버가 이미 붙어 있고(익명 계정 자동 발급, 기기 간 동기화, 세이브 이력 10판 보관), 관리자 페이지로 계정과 세이브를 들여다볼 수 있다. 자동 플레이 E2E 가 1층부터 엔딩까지를 회귀로 지킨다 |
| **발표** | 아래 「발표 3분 구성」 |

## 발표 3분 구성 (트랙 1 발표용 초안)

1. **0:00–0:30 — 문제** 수집형 RPG 의 성장은 대개 레벨 노가다로 수렴한다. 그걸 막고
   "만들어서 넘는다"로 바꾸면 어떻게 되는지가 이 게임의 질문이다.
2. **0:30–1:20 — 게임** 베이스캠프 → 숲 원정(소란도와 정산) → 공방 제작(미니게임으로 품질 결정)
   → 탑 관문. 데모 영상 그대로.
3. **1:20–2:20 — 만든 방법** AI 에게 무엇을 맡겼고 사람이 무엇을 정했는지
   (`docs/DEV_PROCESS.md` 4절이 그 목록이다). 특히 밸런스는 감이 아니라
   시뮬레이션(`scripts/sim/gateCheck.ts`)으로 합격선을 정해 두고 그 선을 지키게 했다는 점.
4. **2:20–3:00 — 지금 상태와 다음** 1~50층·엔딩까지 완주 가능, 기기 간 세이브 동기화 동작.
   다음은 콘텐츠(26~49층 고정 구성)와 모바일 조작.

## Codex 항목에 대해

규정은 **개발 과정에 Codex 활용을 요구**하고, 심사 5항목에도 「Codex 협업」이 들어 있다.
이 저장소는 지금까지 Claude Code 로 작업했고, Codex 로 진행한 부분은 아직 없다
(무엇을 어떻게 했는지는 `docs/DEV_PROCESS.md` 에 사실대로 적어 두었다).

**그래서 지금 상태로는 그 칸에 쓸 내용이 없다.** 선택지는 둘이다.

1. **접수 전에 실제로 Codex 로 작업한다.** 규정이 *"기존 프로젝트도 챌린지 기간 중
   새 개발을 문서화하면 참가 가능"* 이라고 열어 두었으므로, 남은 작업 중 하나를
   Codex 로 돌리면 그때부터 사실대로 쓸 내용이 생긴다.
   후보는 `docs/DEV_PROCESS.md` 맨 아래 표에 있다.
2. **비워 둔다.** 가점 항목이라 비워도 접수 자체는 된다. 다만 심사 항목에
   들어 있으니 점수에는 불리하다.

어느 쪽이든 **하지 않은 일을 한 것처럼 적지는 않는다.**
